# Detailed-Design-Skill (SWE.3)

## 규칙
1. 각 컴포넌트를 **모듈**(소스/헤더 쌍 단위)과 함수로 분해한다.
2. **특정 수준 이상의 모듈**에는 인터페이스를 **반드시** 정의한다. 기준: 다른 모듈이 호출하는 공개 함수가 1개라도 있으면 인터페이스 정의 대상이다. 컴포넌트 내부에서만 쓰는 헬퍼는 `static` 함수로 두고 인터페이스를 정의하지 않는다.
3. 인터페이스가 정의된 모듈은 **오직 그 인터페이스를 통해서만** 통신한다(공개 헤더에 없는 심볼 접근 금지).
4. **클린 코드** 원칙: 의미 있는 이름, 작은 함수, 부작용 최소화, 중복 제거, 매직 넘버 금지(명명된 상수), 주석은 "왜"를 설명.
5. **단일 책임 원칙**: 모듈/함수당 변경 이유는 1개. 한 함수가 여러 일을 하면 분리한다.
6. 설계 단계에서 코드 품질 한도를 예측한다: 함수 순환 복잡도 ≤ 10이 되도록 분기를 쪼갠다.
7. 함수 설계는 구현 스킬 규칙과 일치시킨다: 모든 함수는 반환값을 가지며(적절한 값이 없으면 정상 실행 여부를 나타내는 상태 코드), 단일 반환 지점.

## 산출물 (`docs/detailed-design/`)
- `<component>.md` (컴포넌트별): 모듈 목록, 모듈별 책임, 공개 인터페이스(시그니처·사전/사후조건·오류 코드), 내부 함수 목록, 데이터 구조, 함수별 로직(의사코드 또는 흐름도·상태 전이), 오류 처리.
- ID: 모듈 `MOD-nnn`, 함수 `FN-nnn`. 상위 아키텍처 컴포넌트/인터페이스 ID와 추적.

## 완료 조건
- 모든 공개 모듈에 인터페이스 정의, 모든 함수가 책임 1개로 서술됨.
- 아키텍처 ↔ 상세 설계 ↔ 요구사항 양방향 추적 100%.
- `review-skill`의 상세 설계 체크리스트 통과.
