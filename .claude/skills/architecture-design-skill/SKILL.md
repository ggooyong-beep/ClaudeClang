# Architecture-Design-Skill (SWE.2)

## 규칙
1. 아키텍처는 **컴포넌트**를 정의하고, 각 컴포넌트의 **인터페이스를 반드시** 정의한다. 인터페이스 없는 컴포넌트는 허용하지 않는다.
2. 컴포넌트 간 연결은 **오직 인터페이스를 통해서만** 한다. 다른 컴포넌트의 내부 함수·전역 변수·구조체 필드에 직접 접근하는 설계/코드는 위반이다.
3. **응집력은 높이고 결합도는 낮춘다.** 컴포넌트당 책임 1개, 의존 방향은 단방향(순환 의존 금지), 의존은 구체 구현이 아닌 인터페이스(헤더의 함수 선언/함수 포인터 테이블)에 둔다.
4. **모듈화·캡슐화·SOLID**를 준수한다. C에서는 불투명 타입(opaque type), `static` 내부 링키지, 공개 헤더/비공개 헤더 분리로 캡슐화한다.
5. 요구사항 → 컴포넌트 할당이 100%여야 한다(할당 안 된 요구사항, 요구사항 없는 컴포넌트 모두 금지).
6. 동적 거동(상태, 시퀀스, 타이밍), 자원 소모 목표, 설계 대안과 선택 근거를 기록한다.

## 인터페이스 정의 항목
이름, 제공/요구 컴포넌트, 함수 시그니처, 파라미터 단위·범위, 반환값(성공/오류 코드 열거), 사전/사후조건, 호출 순서·동시성(재진입성), 오류 처리 책임.

## 산출물 (`docs/architecture/`)
- `architecture.md`: 구조도(Mermaid 또는 PlantUML 텍스트), 컴포넌트 표, 의존성 표, 동적 거동, 설계 결정.
- `interfaces.md`: 위 항목을 갖춘 인터페이스 명세. ID `IF-nnn`.
- `traceability.md`(요구사항 문서 것을 갱신): FR/NFR/SAF ↔ 컴포넌트/인터페이스.

## 완료 조건
- 모든 컴포넌트에 인터페이스가 있고, 의존 그래프에 순환이 없다.
- 요구사항 ↔ 아키텍처 양방향 추적 100%.
- `review-skill`의 아키텍처 체크리스트 통과.
