# Requirements-Skill (SWE.1)

## 규칙
1. 요구사항은 **기능**과 **비기능**으로 구분한다.
2. **기능 안전 요구사항**은 일반 요구사항 문서에 섞지 않고 별도 문서(`docs/requirements/safety-requirements.md`)에서 관리한다. 일반 문서에는 안전 요구사항 ID만 참조한다.
3. 비기능 요구사항은 **품질 / 제한 / 제약사항**으로 구분한다.
   - 품질: **ISO/IEC 25010** 품질 특성(기능 적합성, 성능 효율성, 호환성, 사용성, 신뢰성, 보안성, 유지보수성, 이식성)과 하위 특성 중 하나에 분류한다.
   - 제한(limitation): 시스템이 제공하지 않는 것/한도(예: 최대 동시 처리 수).
   - 제약(constraint): 설계·구현에 부과되는 외부 조건(예: 언어, 툴체인, 메모리 크기, 표준 준수).
4. **양방향 추적성**: 모든 요구사항은 상위(이해관계자/시스템 요구) ↔ 하위 산출물(아키텍처, 상세 설계, 구현, 단위/통합/시스템 테스트)과 추적되어야 한다. 추적 누락이 있으면 산출물은 미완성이다.
5. 각 요구사항은 원자적이고(검증 조건 1개), 모호어("적절히", "빠르게", "등")가 없으며, 측정·검증 가능해야 한다. 값이 불명확하면 지어내지 말고 질문 목록(open issues)으로 돌려준다.

## 산출물 (`docs/requirements/`)
- `software-requirements.md`: 표 형식 — `ID | 유형(기능/품질/제한/제약) | ISO25010 특성 | 기술 | 검증 방법 | 상위 ID | 우선순위`
  - ID 규칙: 기능 `FR-nnn`, 품질 `NFR-Q-nnn`, 제한 `NFR-L-nnn`, 제약 `NFR-C-nnn`, 안전 `SAF-nnn`.
- `safety-requirements.md`: 기능 안전 요구사항(ASIL, 안전 목표 추적 포함).
- `traceability.md`: 추적 매트릭스. 요구사항 ID 행 × (아키텍처 / 상세 설계 / 소스 / 단위 TC / 통합 TC / 시스템 TC) 열. 후속 단계가 진행될 때마다 갱신한다.

## 완료 조건
- 모든 항목이 유형 분류와 검증 방법을 가진다.
- 안전 요구사항이 별도 문서에 있다.
- 리뷰 스킬(`review-skill`)의 요구사항 체크리스트 통과.
